# Tamdev CMS Roadmap v1.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Projects, Profile, and Work Experience out of the Admin Content menu into self-contained dynamic section blocks in Theme Customize, add static Header (logo/logo+text/text + resume) and Copyright blocks, add a Certificates template section, and add JSON theme import.

**Architecture:** Extend `site_themes.sections` (`SiteSection[]`) so each theme is 100% self-contained in JSONB with no Supabase schema migration. Static blocks (`header`, `copyright`) are pinned at the top and bottom of `CustomizeSite`, while dynamic sections (`about`, `background`, `work`, `certificates`) store scalar settings and repeatable `items[]` arrays in `draft_settings` / `published_settings`, with read-only fallbacks to legacy Supabase tables when a section is unseeded.

**Tech Stack:** React 18, TypeScript, Vite, Tailwind CSS, Framer Motion, Lucide React, Swiper, Supabase JS.

**Spec:** `docs/superpowers/specs/2026-11-25-tamdev-cms-v1-2-design.md`

## Global Constraints

- Only **Social Links** (`/admin/socials`) remains in the Admin Content menu; Projects, Profile & Resume, and Work Experience are removed from the sidebar and redirected to `/admin/customize`.
- No Supabase SQL migration is required; all theme data lives in `site_themes.sections` JSONB.
- Resume PDF upload lives in the **Header** static block only (intentionally excluded from the `about` / Profile section).
- Uploaded media continues to use `uploadPortfolioFile` in `src/lib/storage.ts` (`portfolio-media` bucket).
- Existing live themes without `header`, `copyright`, or seeded `items` must not lose content on deploy: components fall back to legacy tables/defaults when `settings` fields are `undefined`.

## Review Focus

1. **Importing malformed or legacy JSON files:** Importing a `.json` file that is invalid JSON, missing `sections`, has unknown `type` values, or lacks `published_settings` must show a clear error or normalize cleanly without crashing `ThemesDashboard` or `PortfolioPage`.
2. **Pre-v1.2 live themes missing `header` or `copyright`:** Rendering `PortfolioPage` or opening an older theme in `CustomizeSite` when `header`/`copyright` are absent from `sections` must still render `Navigation` and `Copyright` with defaults and auto-pin them in the editor.
3. **Zero-downtime fallback vs. intentional empty list:** If a user intentionally deletes all items in `work` or `background` (`items: []`), the component must render empty (not fall back to legacy DB rows); fallback only triggers when `settings?.items === undefined`.
4. **Logo mode with missing `logoUrl`:** Selecting `'logo'` or `'logo_with_text'` in Header when `logoUrl` is empty must gracefully render `brandText` instead of a broken `<img>` icon.
5. **Social Links & Contact independence:** Removing `/admin/profile` must not break `Contact.tsx` social links (`social_links` table) or `contact_title` / `contact_subtitle` editing.
